01무엇을 만든 것인가

교사가 수업 전에 영상을 담아두고, 교실에서는 재생 버튼 하나로 한 차시를 진행하게 하는 것이 이 제품의 전부입니다. 나머지 기능은 그 흐름을 받쳐주는 부속입니다.

영상 라이브러리 수업 준비 교실 ───────────── ───────────── ───────────── 검색 · 필터 · 정렬 → ★ 즐겨찾기 → ▶ 수업시작 104편 / 23분류 🎬 영상담기 전체화면 연속재생 학급에 커리큘럼 연결 → ▶ 차시 바로 열기

참고한 상용 사이트는 jjinbro.co.kr/sj 의 「신개념 교실체육 스마트점프」입니다. 화면 구성(좌측 사이드바 + 상단 영역 탭 + 카드 그리드 + 영상담기)은 그 구조를 따랐고, 권한 제어·날짜별 출석·수업 리포트는 이번에 새로 설계했습니다.

02두 개의 배포본

같은 프론트 코드가 백엔드만 갈아끼워 두 곳에서 돕니다. 이걸 이해하면 나머지는 쉽습니다.

[브라우저] ──google.script.run──▶ [Apps Script] ──▶ [구글 시트 10탭] ← 풀스택 │ └──── 같은 app.js ────▶ [local-backend.js] ──▶ [localStorage] ← 데모

web/local-backend.js 가 google.script.run 과 똑같은 인터페이스를 localStorage 위에 구현합니다. 그래서 프론트는 자기가 어느 백엔드에 붙어 있는지 모릅니다.

풀스택 판은 아직 배포되지 않았습니다. 지금 도는 사이트는 데모라 방문자마다 데이터가 따로 놉니다. 여러 교사가 실제로 함께 쓰려면 06 개발 워크플로 의 배포 절차를 밟아야 합니다.

구글 시트 10개 탭이 곧 DB입니다. 열 이름이 한글 그대로 키로 쓰이므로 열 이름을 바꾸면 코드가 깨집니다.

알아둘 설계 규칙

  • 소유자 열이 곧 접근 제어입니다. classes · equipment · schedules 는 소유자로 걸러 조회합니다. 단 api_classes 만 관리자에게 전체를 돌려줍니다.
  • 영상이 0건인 분류는 화면에 안 나옵니다. 분류를 미리 다 적어두고 영상을 채워가도 화면이 깨지지 않습니다.
  • 출석은 (수업, 날짜) 단위로 교체됩니다. 저장해도 다른 날짜 회차는 그대로 남습니다.
  • 비밀번호는 SHA-256 해시로만 저장합니다. 평문이 시트에 들어가면 안 됩니다.
  • 영상·카테고리는 6시간 캐싱됩니다. 시트를 직접 고쳤으면 Apps Script 에서 캐시비우기 를 실행하세요.

권한 제어는 두 겹입니다. 화면에서는 data-role 속성으로 메뉴를 감추고, 그 뒤에서 guardRoute() 가 URL 직접 접근을 막습니다. 서버 쪽도 roleOf_() 로 다시 확인하므로 API 를 직접 호출해도 통과하지 못합니다.

안전장치

자기 자신의 권한·상태는 바꿀 수 없고, 마지막 관리자는 강등할 수 없습니다. 아무도 관리할 수 없는 상태가 되는 걸 막기 위한 것이니 지우지 마세요.

보안 한계

비밀번호를 SHA-256 으로 해시하지만 솔트가 없고 반복 해싱도 하지 않습니다. 교내 시범 운영 수준이지 은행급이 아닙니다. 실제 학교 계정을 받아 운영할 계획이면 구글 로그인으로 전환하는 편이 안전합니다.

06개발 워크플로

저장소 루트에서 npm install 한 번, 이후는 아래 명령만 씁니다.

명령하는 일언제

구글 시트 연동판 배포 (아직 안 됨)

  1. 시트 채우기 — 스마트점핑_DB.xlsx 를 구글 시트에서 파일 → 가져오기 → 업로드 → 스프레드시트 바꾸기. 10개 탭이 그대로 들어갑니다.
  2. Apps Script 프로젝트 — apps-script/ 의 6개 파일을 붙여넣습니다. index · css · js 는 반드시 HTML 파일로 만들고 확장자는 붙이지 않습니다. 기본 코드.gs 는 지웁니다.
  3. 시트 연결 — 00_설정.gs 의 TARGET_SHEET_ID 에 시트 ID를 넣습니다. 시트에서 확장 프로그램 → Apps Script 로 열었다면 비워둬도 자동으로 잡습니다.
  4. 웹앱 배포 — 배포 → 새 배포 → 웹 앱 / 실행 계정 나 / 액세스 링크가 있는 모든 사용자.

영상 추가하는 법

가장 자주 하게 될 작업입니다. videos 탭에 행을 넣고 youtube_id 만 채우면 썸네일·재생이 자동으로 붙습니다.

https://www.youtube.com/watch?v=AbCdEfGh123 → AbCdEfGh123 https://youtu.be/AbCdEfGh123 → AbCdEfGh123

대량으로 넣을 때는 npm run verify:yt 로 생존 · 임베드 허용 · 재생시간을 먼저 검증하세요. 이 검증을 건너뛰면 삭제되거나 외부 재생이 막힌 영상이 섞여 교실에서 검은 화면이 뜹니다.

07반드시 지킬 것

전부 실제로 한 번씩 사고가 났던 지점입니다. 읽고 넘어가면 같은 자리에서 또 걸립니다.

  1. 루트 index.html 을 직접 고치지 않는다

    생성물입니다. apps-script/ 를 고치고 npm run build. 직접 고친 내용은 다음 빌드에 사라집니다.

  2. String.replace(a, b) 로 코드를 치환하지 않는다

    치환 문자열 안의 $$ 를 $ 하나로 축약합니다. 이것 때문에 $$ 헬퍼 함수가 통째로 망가져 로그인 버튼이 죽은 적이 있습니다.

    반드시 함수형으로: s.replace(a, () => b)

  3. 01_초기설정.gs 를 통째로 다시 쓰지 않는다

    write-setup-gs.js 는 파일 전체를 덮어써서 손으로 고친 계정·소유자·TARGET_SHEET_ID 를 날립니다. 영상만 바꿀 때는 npm run seed 를 쓰세요. 이쪽은 영상 블록만 외과적으로 교체하고 9가지 무결성 검사를 통과해야 저장합니다.

  4. 스키마를 바꾸면 세 곳을 같이 고친다

    00_설정.gs 의 HEADERS → 02_API.gs 의 읽기/쓰기 → web/local-backend.js 의 같은 함수. 한쪽만 고치면 시트판과 데모판이 어긋납니다.

  5. 시드 구조를 바꾸면 ver 를 올린다

    build-static.js 의 sj-s6- → sj-s7-. 안 올리면 방문자 브라우저의 localStorage 가 옛 구조를 계속 붙들고 있어 화면이 어긋납니다.

  6. 새 API 는 양쪽 백엔드에 다 넣는다

    02_API.gs 에만 넣고 local-backend.js 를 빠뜨리면 데모 사이트에서만 조용히 실패합니다. 함수 이름·인자 순서·반환 모양을 똑같이 맞추세요.

08왜 이렇게 돼 있나

"이건 왜 이렇게 짰지?" 싶을 만한 결정들의 배경입니다. 잡았던 버그가 곧 설계 이유인 경우가 많습니다.

보이는 것이유
썸네일이 onerror 가 아니라 크기 검사로 대체된다 유튜브가 없는 maxresdefault 에 404 대신 회색 placeholder 를 200 으로 주는 경우가 있어 onerror 가 안 걸립니다. 지금은 naturalWidth < 320 이면 hqdefault 로 갈아끼웁니다.
담은 영상·즐겨찾기가 계정별 맵에 저장된다 초기 데모판은 userId 를 받고도 무시해 단일 키에 저장했습니다. 교사가 담은 영상이 학생 계정에도 그대로 보였습니다.
api_saveClass 가 값 없는 필드를 유지한다 sched 를 빼고 부르면 학급의 커리큘럼 연결이 조용히 지워졌습니다. 지금은 undefined 면 기존 값을 그대로 둡니다.
앱 진입점이 스크립트 맨 끝에 있다 세션 복구 코드가 GUEST_NAV 선언보다 먼저 돌아 첫 화면이 빈 채로 떴습니다.
시드 스케줄이 영상ID를 직접 안 적는다 ID를 박아두니 영상 목록이 바뀔 때 "명상 + 명상 + 타이머" 같은 엉뚱한 차시가 됐습니다. 지금은 소분류에서 골라 명상 → 준비운동 → 본운동 → 정리 흐름으로 엮습니다.
본문 색이 n-500 이상만 쓴다 n-400(#94a3b8)은 흰 배경에서 2.56:1 로 WCAG AA(4.5:1) 미달이었습니다. 어두운 배경에서는 반대로 n-600 이 2.49:1 이라 밝은 톤을 씁니다.
재생 실패 시 5초 뒤 자동으로 다음 임베드가 막힌 영상 하나에 수업이 멈추면 안 됩니다. 사유를 띄우고 넘어갑니다.
